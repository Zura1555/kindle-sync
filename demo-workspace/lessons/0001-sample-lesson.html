SQL Naming Conventions — Why snake_case?

Lesson 0001  ·  ~10 minutes
🎯 Mission Connection: Your inherited PostgreSQL database uses specific naming conventions. Understanding why they were chosen lets you write new tables and columns that blend in seamlessly.

The Case-Folding Trap

PostgreSQL has a rule that catches newcomers: unquoted identifiers are folded to lowercase.

If you write:

CREATE TABLE UserProfiles (
    UserID    SERIAL PRIMARY KEY,
    FirstName TEXT
);

PostgreSQL silently converts every name to lowercase — you get a table called userprofiles with columns userid and firstname.

💡 Key Insight: PostgreSQL folds unquoted identifiers to lowercase to comply with the SQL standard. This is why snake_case is idiomatic — it reads naturally in lowercase.

The Quoting Escape Hatch

If you must preserve case, use double-quotes:

CREATE TABLE "UserProfiles" (
    "UserID" SERIAL PRIMARY KEY
);
-- Now you MUST quote it every time:
SELECT "UserID" FROM "UserProfiles";   -- correct
SELECT UserID FROM UserProfiles;       -- ERROR: does not exist

Once you quote once, you must quote forever.
