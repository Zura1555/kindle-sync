SQL & PostgreSQL Glossary

Key terms from the lessons. Designed for quick look-up on browser or Kindle.

C

camelCase
A naming style where compound words have no separators, and each word after the first starts with a capital letter: customerOrders. Requires double-quoting in PostgreSQL. Not idiomatic for SQL.→ Lesson 0001
Constraint
A rule enforced by the database on a column or table. Types include NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, and CHECK.→ Lesson 0001

F

Foreign Key (FK)
A column that references the primary key of another table. Enforces referential integrity. Naming: {referenced_table}_id.→ Lesson 0001

P

PascalCase
A naming style where every word starts with a capital letter: CustomerOrders. Like camelCase but with a leading capital. Same quoting problems in PostgreSQL.→ Lesson 0001
Primary Key (PK)
A column (or set of columns) that uniquely identifies each row. PostgreSQL auto-creates a B-tree index on primary keys.→ Lesson 0001

Q

Quoted Identifier
An identifier wrapped in double-quotes: "MyTable". Preserves exact case but must be quoted in every subsequent query — tedious and error-prone. Avoid unless migrating from a case-sensitive database.→ Lesson 0001

S

snake_case
Lowercase words separated by underscores: customer_orders. The PostgreSQL standard because unquoted identifiers are folded to lowercase. Used by Python, Ruby, and MySQL communities.→ Lesson 0001
SQL Standard
The ANSI/ISO specification that defines SQL syntax and behavior. PostgreSQL closely follows it. The standard specifies that unquoted identifiers are case-insensitive, which is why PostgreSQL folds to lowercase.→ Lesson 0001
